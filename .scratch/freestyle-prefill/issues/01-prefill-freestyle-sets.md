# Pre-fill freestyle workouts from previous results

Status: closed
Category: enhancement

Starting a workout from a program plans its sets with `planSets` (src/lib/plannedSets.ts): previous
results' warmup sets, at least as many work sets as last time, weights/reps carried over. Starting from a
**workout template** and **adding an exercise** to a live workout both create blank work sets instead
(target count, no weight/reps, no warmups).

Question: should these two paths plan their sets with `planSets` as well (template: target_sets as the
target, no prescription)? Decided out of scope for the planned-set-generation refactor (2026-10-24) because
it changes behaviour.

### Agent Brief

**Category:** enhancement
**Summary:** Template starts and exercises added mid-workout get planned sets from previous results,
like program starts.

**Current behavior:** both create blank work sets (template: its `target_sets`; added exercise: 3), no
warmups, no weights or reps.

**Desired behavior** (terms as in `GLOSSARY.md`):
- Starting from a workout template: each exercise's planned sets come from `planSets` with no
  prescription, the template exercise's `target_sets` as the target, and that exercise's previous
  results — previous warmup sets first, at least as many work sets as last time, weights/reps carried
  over, reps left empty after a too-heavy work set.
- Adding an exercise to an in-progress workout: the same, with the add call's target (default 3).
- An exercise never done before keeps today's behaviour (target-many empty work sets).
- Suggested weights and too-heavy flags unchanged.

**Key interfaces:** `planSets` (src/lib/plannedSets.ts) is the single source of planned sets;
`getPreviousResultsInternal` supplies previous results. `startWorkoutFromTemplate` and
`addExerciseToWorkout` keep their signatures and return shapes.

**Acceptance criteria:**
- [ ] A template start for an exercise with previous results returns sets equal to `planSets`' output.
- [ ] An added exercise with previous results gets the same planned sets as a template start would.
- [ ] Exercises without history still get target-many empty work sets.
- [ ] `npm test`, `npx tsc --noEmit`, `npm run build` pass.

**Out of scope:** making template start atomic (separate ticket), Easy Week for templates, UI changes.

### Resolution (2026-10-25)

`startWorkoutFromTemplate` and `addExerciseToWorkout` plan their sets with `planSets` from each exercise's
previous results (template: its target_sets; added exercise: the call's target). Template suggestions now
come from the same previous results via `setRules.suggestedWeight` instead of a second fetch. The rules
themselves are covered by the planSets tests (including "no history → target-many empty work sets");
the two actions need a database and were not run in tests.
